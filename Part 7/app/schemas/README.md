# Room schema snapshots and historical test fixtures

`app/build.gradle.kts` exports Room schemas via KAPT to this directory; androidTest assets include it. Baseline `56b37aa` already committed **MemoryDatabase v6, v7 and v8**. The old README saying version 5 was current was stale.

- `com.jarvis.assistant.data.memory.MemoryDatabase/6.json`, `7.json`, `8.json`: existing committed production schema exports, retained unchanged.
- `com.jarvis.assistant.security.sandbox.AuditDatabase/1.json`: generated by Room after enabling `exportSchema=true`. This changes schema metadata only, not the audit DB version, encryption policy or table contents.
- `com.jarvis.assistant.data.memory.HistoricalV1Database/1.json` and `HistoricalV5Database/5.json`: compiler-generated **test fixtures**, not recovered shipped schema exports. Their annotated entities live only in `src/androidTest/.../HistoricalMemorySchemas.kt`.
- `com.jarvis.assistant.data.memory.MemoryDatabase/1.json` and `5.json`: copies of those generated historical test fixtures, placed under the production class asset path so `MigrationTestHelper(..., MemoryDatabase::class.java, ..., SQLCipherFactory)` can load both endpoints. No production auto-migration or version bump uses these files.

Historical source provenance:

- V1 memory declaration: `git show d227bca^:'Part 7/app/src/main/java/com/jarvis/assistant/data/memory/MemoryEntity.kt'`, six original fields, before the v2 provenance additions.
- V5 memory declaration: `git show 81c5ec1:'Part 7/app/src/main/java/com/jarvis/assistant/data/memory/MemoryEntity.kt'`, before v6 sync fields. The v5 database entity list is verified from `MemoryDatabase.kt` at that same commit. Chat/mission/notification entity table declarations are unchanged from those historical definitions.

Only persisted entity declarations are reproduced, with renamed Kotlin test types; convenience methods and constants are omitted/inlined. Room generates actual SQL, identity hashes, indices and field metadata. To refresh these **fixtures**, run `:app:compileDebugAndroidTestKotlin`, then copy the two Historical schema JSON files into the matching `MemoryDatabase/1.json` and `5.json` paths and review their diff. Do not relabel them as original release artifacts or invent intermediate v2–v4 exports.

## Encrypted migration tests

`RoomMigrationInstrumentedTest` uses a real `SupportOpenHelperFactory` from SQLCipher with Room's corruption-preserving SQLite callback, and `MigrationTestHelper.createDatabase` / `runMigrationsAndValidate`. It never invokes migration objects' `migrate()` manually. It verifies v1→v5 validation, opens the result using a real historical-v5 Room implementation, then opens it using production Room v8 with the registered migrations and checks preserved memory/chat/mission/notification records. Separate tests reject wrong/empty SQLCipher keys without deleting data and retain corrupt ciphertext for explicit recovery from a known-good backup.

The test uses disposable named databases and independent random test keys, not the live `jarvis_memory.db` or its Keystore alias. It tests the real SQLCipher/Room factory and callback but does not reproduce OEM Keystore invalidation or the full production fixed-path plaintext-to-encrypted swap. Existing `DatabaseKeyStoreInstrumentedTest` covers wrapped-key tamper rejection separately. Original released binaries/schema snapshots were unavailable, so historical entity-fixture validation is not proof of upgrade compatibility with every previously distributed APK.

Compilation is not execution: these tests need an Android emulator/device and native SQLCipher. No runtime result is claimed until `connectedDebugAndroidTest` actually executes; see the Phase A report for checks run in this session.
