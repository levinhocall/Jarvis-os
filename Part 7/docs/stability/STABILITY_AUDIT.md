## Verified existing protections (preserve)

MicrophoneOwnership has identity-based leases; production AudioPipelineManager delegates to AudioRecorder. VoiceSessionManager owns reconnect generation, single job, connection mutex, bounded attempt count/backoff and stop barrier; Gemini transport externalReconnectManagement avoids duplicate reconnect ownership. Foreground promotion handles failure and blocks mic when not eligible. Service scopes are cancelled onDestroy. Room initialization is app-owned IO with typed wait deadlines and no destructive fallback. These are code findings, not proof of phone behavior.

Screen lock/unlock, idle, recents removal, process death, permission revocation, keyboard/dialog/split screen, OEM battery handling, network switch and secure/custom-rendered windows require Android execution. 100 cold starts, 100 voice cycles, 2-hour voice soak, 24-hour background test, CPU/RAM/ANR traces: NOT RUN until real execution is recorded. ## Fix scope and evidence

- A1/A9: existing health facade now uses one synchronized reducer. Only a real service connection creates a token. Settings refresh/rebind/events/queue cleanup cannot fabricate a connection or hide a permission error. A readable snapshot is separate evidence from an accepted mutation, gesture completion and verified application outcome. Tests use fake monotonic time, no Android singleton impersonation.
- A2/A6: event callbacks enqueue one coalesced metadata job (minimum 250 ms interval). Existing legacy searches share node/depth/time budgets; semantic traversal and ancestor searches are bounded too. The existing mutation executor has 16 admission slots and a caller deadline including queue/Main dispatch wait. Probe work is owned, single-flight and event-driven; idle silence is not failure.
- A3: every gesture entry point uses the same per-service ticket gate with token-bound callbacks and a 2.5 s timeout. Timeout is an unknown result, so admission stays closed until a real callback or explicit local recovery. Recovery invalidates old task epochs and permits fresh work, without replaying the timed-out action.
- A4/A5: prefer only active/focused application/system windows, ignore inactive applications/IME/overlay candidates, acquire candidate roots once. Metadata caches bind to service token and window revision. New snapshot walkers cap acquisition as well as visits, release acquired children/root owners, and retain bounded child handles until traversal ends so API 26–32 node-pool identity reuse cannot prune valid branches. Stale/cancelled traversals clean up.
- A7/A8: existing AudioPlayer queue bounded to 2 MiB/512 frames; each dequeued frame retains generation through playback. Release is terminal; lazy hardware initialization cannot recreate a released track; stop failure still attempts release. Playback consumer exceptions are isolated. Existing AudioRecorder has zero-read backoff/stall detection, a three-attempt recovery budget and typed terminal failure. Hardware cleanup retains the exact microphone lease until its job completes; voice/wake transitions cooperatively wait at most 1.5 s then report failure, never grant competing ownership. These are source/host-policy results; native hardware behavior remains unverified.
- A10: new diagnostics contain fixed issue categories, monotonic durations and bounded (32) metadata history; no screen labels, message contents, OTPs or raw exception details. Existing Permissions diagnostic dialog now shows real status and offers Cancel task & probe plus Android Settings. This task is not a repository-wide sensitive-log certification.
- A15: absent/empty before or after observations cannot verify click/scroll success. Verification is bound to the service generation; stale callbacks cannot heal a replacement.
- A16/A17: delayed legacy work is scoped to expected app packages, one primary call tap plus a recognized optional confirmation, and exact requested draft when available. Different drafts are preserved. Handler exceptions cancel owned pending work and record only typed errors. Queueing a send/clearing the composer is not delivery evidence.
